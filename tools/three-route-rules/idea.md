# Three Route Rules (idea card)

- Module: computer-science-3-5-algorithms-that-help-some-more, grade 3-5. Codes: E3-ALG-IM-03, E4-ALG-IM-03, E5-ALG-IM-03
- Format / family: simulator / none. Fit: good, because the rule is the input and four trips are the output.
- One idea: A walking app can pick routes by three rules (fastest, fewest street crossings, no stairs); run each rule for four travelers (a kid walking to school, a wheelchair user, a parent with a stroller, a jogger) across the same town map and see who each rule helps and who it lets down, then write a rule that works for more of them.
- How it plays (solo student by default):
  - First screen: a town map with a school, a library and a park, four travelers at their homes, and three rule buttons.
  - Core loop: pick a rule; each traveler's route draws on the map with a trip card: minutes, crossings, stairs, and a face. Fastest sends the wheelchair user to a staircase shortcut; fewest crossings makes the jogger's trip long; no stairs helps the stroller and the wheelchair but adds 6 minutes for the kid.
  - Score sheet: a grid of 3 rules by 4 travelers fills in with helped, OK and let down.
  - Make a rule: combine conditions ("no stairs, then fastest") and test it against all four.
  - The aha or the end state: no rule is neutral; each one picks who comes first, and the people who make the app choose that.
- Standards, one line per code:
  - E3-ALG-IM-03: run the three rules and say who each one helps and who it lets down.
  - E4-ALG-IM-03: compare the score sheet and explain why the same map gives different routes.
  - E5-ALG-IM-03: write a combined rule, test it with all four travelers and explain the trade-off left.
- Not like: line-leader-picker (K-2, turn rules for a class); algorithm-audit (grade 6-8 bias in a scoring formula); sorting-showdown (algorithm speed).
- Art: generated town map scenes and people (illustrated) travelers.
