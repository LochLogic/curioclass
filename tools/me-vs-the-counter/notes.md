## What it teaches

Children collect a count by tapping or making a paper tally, then compare it with a floor sensor's count of the same hits.
They use a table and a picture graph to decide which ball bounces most in this model.

## Key skills

- Count one event at a time.
- Compare two ways of collecting the same data.
- Notice quick hits that are easy to miss.
- Make a prediction, then use measured counts to decide.
- Read a picture graph with one dot for each hit.

## Support at home

- Count an everyday repeated sound together, such as taps on a table. Compare your counts and try again slowly.
- Drop a soft object safely onto the floor and count its first touch, even if it does not bounce back up.
- Make a row of small objects for each of two counts. Ask which row has more and how you can tell.

## A 5-minute start

Project Bounce Lab. Half the class counts out loud or makes tallies; one helper taps Bounce each time the ball touches
the pad. The other half watches the Counter. Press Drop immediately; the instructions do not delay the fall.
Look at the timeline together. Teal ticks are pad hits, orange hand marks are taps, and joining lines show matched
events. Yellow rings mark missed hits, and gray rings mark extra taps. Try Again, then Slow. Switch class roles.

## The modes

**Bounce Lab:** choose any ball. Drop and tap, or use Our count after the drop to enter a paper tally from 0 to 30.
Paper totals have no timestamps, so the hand row is hidden. The sensor row stays visible.

**Bounciest Ball:** point to a prediction, then tap it on the question card, or Skip. Drop all four balls in any order.
The edge table keeps the latest three finished class counts per ball. A fourth replaces the oldest. The sensor count
stays the same. Show the chart unlocks only when every ball has been measured. Tap the longest row to answer.
Back to gym returns to the experiment; Start over clears this mode. Switching modes keeps each mode's finished work.

## Talk together

- What did the sensor feel? How did the computer get its count?
- Where did our counting get difficult? What changes when we use Slow?
- Why should every ball start at the same height?
- Did the measurements agree with our prediction? Which row is longest?
- Why does the beanbag still have one hit?

## Good to know

The sensor is simulated. It counts every floor contact, including the initial landing. The computer follows fixed
rules; it does not learn. This is a model, not a claim that every real ball gives these counts on every surface.
Every ball starts 1.8 meters above the floor. Gravity is 9.8 meters per second squared. Bounce factors are 0.90,
0.85, 0.745 and zero; bounce flights shorter than 0.25 seconds are omitted. Sensor totals are 15, 10, 6 and 1.
Slow plays the same physical times at half speed, and the timeline always covers ten physical seconds.

Taps match hits in order within 0.15 seconds early to 0.40 seconds late, maximizing pairs before minimizing time gaps.
An unfinished drop is discarded if restarted or interrupted by a mode switch. All controls stay available during a drop.
D drops; Space taps the hand, including while another button has focus. Enter activates the focused control.
Motion off keeps real timing and sound but replaces arcs with still floor and peak positions.

No class work is saved or transmitted. Only the shared kit's Motion preference persists. Sound starts on. Read speaks
the current hint, even with Sound off. Narration uses browser speech until easy-coach recordings are provided.

Standards: collecting taps and sensor data teaches EK-DAT-DC-08; the timeline, tally totals and picture graph teach
EK-DAT-DI-09; predicting and using the measured longest row teaches EK-DAT-IM-10. 2017 crosswalk: 1A-DA-06, 1A-DA-07.
