## What it teaches

Students choose number, text and Boolean values, debug type errors, and write procedures with local parameters.
They compare the edits needed after a menu change to see how reuse keeps a change in one place.

## Key skills

- Store clearly named values and distinguish their types.
- Join text and convert a number with str().
- Build and call procedures, including a procedure that calls another.
- Pass values into local parameters.
- Refactor copied code and measure the edits a later change needs.

## Support at home

- Ask your child to explain why the number 3 and the text "3" behave differently.
- Describe a repeated household task. Identify a reusable recipe and which details change each time.
- Change one rule in a pretend menu and ask where the instructions would need updating.

## A five-minute start

Open A1. Press Cook and read the error on line 2. Change the quoted "4" to the number 4 and Cook again.
In A2, inspect the stack jar before changing the text values to numbers. The next error shows why labels need text.
Try str(stack) + " pancakes" in the label slot. The Pantry can wrap an expression in str().

## Modes

Tickets has 12 open levels in four sets. A introduces types, B procedures and nested calls, C parameters,
and D refactoring across menu changes. A correct first menu in B-D brings a Manager's note and a new menu.
Edits count one changed slot or one line added, deleted or moved. Undo restores both the card and counter.
Length does not score. A gold ring records meeting the change in one edit or fewer. D10's first change has no par.

Open kitchen starts empty. Use New ticket for up to eight orders and Add a line to write the program.
Both card and tickets save only on this device. Clear saved asks before removing them. No account or network is used.

## Talk about it

- Why does "3" + "2" make "32"? What type does the griddle need?
- Which lines change when one menu item changes?
- What can be a parameter, and which part of the recipe should stay fixed?
- Why might a longer card still be easier to change?

## Good to know

Select a slot to type directly. Enter opens Pantry. A def line has a comma-separated list of blanks.
Add a line inserts below the selected line. Indent puts a line inside a def; Outdent returns it to the main card.
New procedure calls use the current number of blanks. If you change that number, replace an older call using Add a line.
Alt+Up and Alt+Down move the selected line. Ctrl+Z undoes up to 40 edits. Step executes one line; Cook starts from the beginning.
Stop clears the station. Editing pauses a run immediately. The highlighted line stays in the card's scroll window.
The language intentionally has no loops or conditionals. Kitchen counts have finite ranges and recursive calls stop after 20 nested calls.
Every call gets its own parameter jars. Those jars vanish when the call returns; global jars persist for the run.
For a to-go order the label must match exactly; dine-in labels are ignored. Toppings match as a set.
Narration uses the kit's browser speech fallback. The prepared bank voice is easy-coach (Umbriel); recordings were not made.
