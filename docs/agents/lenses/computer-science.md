# Lens: computer science

Subject pre-work, 2026-11-16, in the shape of the core lenses (P5a, docs/PRODUCTION-PATH.md). The expert reads this
before any computer science progression, frame, scope and sequence, unit plan or day. It is a way of seeing, not a
bar: the bar is the computer science part of docs/ADOPTION-BAR-SUBJECTS.md. The standard is the 2026 CSTA PK-12
Computer Science Standards (docs/courses/computer-science/STANDARD.md).

## What good teaching of computer science looks like

**All five concepts, not programming alone.** Algorithms and design, programming, data, systems and security, and
computing and society each get taught days in every band. AI is not a separate unit added at the end: it sits inside
the concepts (data that trains a model, an algorithm that decides, a system that can fail, a society that lives with
it), as the 2026 standards place it.

**Read before write, then modify, then make.** Students first trace and predict what a given program or algorithm
does, then change a working one, then build their own (use, modify, create; predict, run, investigate, modify, make).
A blank editor on day one is a sign of trouble. Worked examples and partly finished programs (Parsons problems,
fill-in code) carry novices.

**Unplugged work teaches the idea; plugged work tests it.** Cards, paper and movement show what an algorithm,
a network packet or a binary number is, without a screen. Then the same idea runs on a device, where the machine
gives honest feedback. Unplugged days are not filler; each names the concept it teaches.

**The notional machine is taught.** Students need a model of what the computer does with each line: one step at a
time, in order, exactly as written, with variables as named boxes that hold one value. Tracing tables and
"be the computer" tasks build it.

**Debugging is taught as a method.** Predict, run, compare, find the first place it goes wrong, change one thing,
test again. Errors are normal and shared. Testing is planned before the program is called done.

**Practices inside content.** Collaboration (pair programming with roles that switch), human-centred design (who uses
this, who is left out), and ethics are practised on the unit's content, not in a separate week.

**Society with evidence.** Privacy, bias, access, law and work are taught with real, dated cases and more than one
view, under the values rule. Students audit and test systems; they do not just discuss them.

**A teacher who is not a specialist can teach it.** Teacher pages explain the content at adult level, give the
common bugs and what each shows, and never assume the teacher can debug on the fly.

## Errors reviewers catch

**Progression**
- A concept owned by no band, or programming taking most days in every band while data, systems or society get one.
- A construct used before it is taught (a loop with a variable counter before variables; nested conditionals before
  single ones).
- Middle school assumes text code when elementary taught only blocks, with no bridge.

**Course frame and scope and sequence**
- A CSTA id taught below its boundary statement, or claimed by a day that only mentions it.
- A Specialty id claimed in the Foundational course where the unit does not already go that far, or an S2 id claimed.
- AI as one late unit with no data or algorithm work under it.
- No unplugged path in a unit (bar criterion 5).

**Unit**
- Students write programs from scratch before any trace, predict or modify task.
- The end-of-unit assessment is vocabulary recall in a doing subject; no program is read, traced or written, no
  rubric for a project.
- Society content with one view only, with no date or source, or with a product promoted.
- A tool with no named job, or one that needs an install, an account or a network to store work.

**Day**
- The goal names a tool or a puzzle ("finish level 6") instead of a concept.
- Code shown with a bug the key does not explain, or a bug students meet with no debugging step taught.
- Equality and assignment confused in wording ("x equals x plus 1" read as a maths statement with no note).
- A claim that coding improves general thinking or school results (bar: unsupported).
- Pair work with no roles, or one student at the keyboard all period.

## Common student misconceptions to plan for (from memory)

- The computer understands intent ("it knows what I meant").
- A variable holds a formula and updates itself, or holds more than one value; assignment read as equality.
- Loops: the counter's last value, off-by-one, the body running once.
- Conditionals: an else that runs too, or both branches run.
- The internet is one place, or "the cloud" is not someone's computer; deleting removes every copy.
- AI is a thinking being, or always right; data is neutral.
