## How the script decides

- **The catalog** is data/tools-concepts.csv: 800 tools, each with a folder in tools/.
- **Named by a plan** means one of two things. The tool is in a day row of data/plans/<course>/days.csv with a mark. Or it has a section, or a row in the reteach table, on a course page docs/courses/<course>/TOOL-ASKS.md. Where both give a mark, days.csv wins. Spines do not count: a spine is not a unit plan.
- **Live** means the folder holds tool.json. This is the same test that set the stage counted in docs/COURSES-STATUS.md. Live tools in the catalog: 83.
- **Passing the teaching test** (BASELINE rule 21) is read from docs/agents/catalog/tables/spec-sort.csv, the catalog read of 2026-11-10. A tool passes when its sort is "fine": every code it carries was read as taught, with no core part of the wording missing. A sort of "small addition" or "rework" does not pass.
- **No record, no pass.** A live tool with no row in that file goes to bin (c) with the reason "no teaching-test record". That count today: 0.
- **Limits.** The catalog read is rough and was not made by playing each tool. No built tool has been played against its spec yet (docs/agents/catalog/verified.txt is empty). A spec fixed after the read does not change a live tool, because the code still follows the old spec. So bin (b) is what the record says today, no more.
